# Ingredient overlay v1

Raw imported names, amounts, tracking metadata and PDF ingredients are never rewritten. The ingredient view derives a separate retrospective layer for both historical and new slots. Food-level analysis is unchanged. Observation-date filtering is unchanged.

Priority: PDF ingredient list > manual rule > disabled inference > automatic inference. PDF ingredients remain intact in storage and export; analytical names are generalized. Existing ingredient tracking metadata is not reused for general categories, so broader categories get their own analytical raw-name identities. Old review records are retained, not silently reassigned to these new identities.

Automatic inference uses explicit name tokens and a small typical-food dictionary: quesadilla includes flour and cheese; burgers include flour and generic meat, cheeseburger also cheese; pizza, bread, pastries, dumplings and pasta receive the general flour category. Explicitly named chicken, pork, beef, dairy, apple, potato, egg, poppy and chocolate are added. The listed grilled-vegetable components are extracted. Unknown recipes stay unresolved; inferred lists are partial, not declarations of absent ingredients. No grams are estimated. Named absence of flour, eggs, milk, butter or cream suppresses that inference. Explicit lactose-free and recognized gluten-free variants remain separate.

Rules are localStorage pain-tracker-ingredient-rules, version 1, keyed by normalized exact food name. They apply to all occurrences of that name; original PDF recipes always have priority. UI offers manual list, inference off and reset to automatic. Edits remount tracker and suggestions so derived counts refresh. Food Tracker and suggestion calculations both use the same overlay, and existing follow-up deduplication counts one ingredient per meal slot. The editor previews the source and general ingredient list. Source names and provenance are retained in the derived objects. Export includes raw food, manual rules and built-in rule version.
